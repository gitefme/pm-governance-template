# Decision Register Example

Reference only; adopt using [the registration procedure](../GOVERNANCE_EXTENSIONS.md#adoption-and-ownership).

```md
# Decision Register

## D-001 — Specific unresolved choice

- State: Open
- Question: The actual choice needed from the user.
- User Inputs: Exact supplied constraints; omit if absent.
- Codex Additions: Recommendation and clearly labeled assumptions.
- Alternatives: Options with consequences and tradeoffs.
- Affected Work: Existing task, epic, and design-source links.
- Needed Before: Planning, implementation, or acceptance and the affected scope.
- Decision: Unanswered.
- Evidence: No decision yet; later record the dated user instruction.
- Supersedes: None.

On confirmation, set State: Confirmed, record the actual decision, its date/scope,
and update the owning durable source and affected plans. A rejected option is not
an implementation requirement. Superseded decisions retain history and link to
replacement evidence. No response is inferred from elapsed time. New scope or a
changed plan needs its own applicable approval and activation.
```
