# Traceability Example

Reference only; adopt using [the registration procedure](../GOVERNANCE_EXTENSIONS.md#adoption-and-ownership).

```md
# Requirement and Verification Traceability

- Basis: dated confirmed inputs and the scope covered by this table
- Updated: YYYY-MM-DD
- Coverage: specified release/package; list exclusions explicitly

| User outcome or requirement | Owning design/architecture rule | Existing task/current plan | Verification and evidence | Open decision |
| --- | --- | --- | --- | --- |
| Faithful requirement wording | Source and section link | Exact current record | Required check; dated result or Pending | Decision link or None |

Review forward coverage (each included requirement reaches a task and check) and
reverse coverage (each included task has a requirement or labeled Codex Addition).
Task records own status. A planned verification method is not a passed result.
Preserve historical snapshots with their scope/date; update current plan links
when a revision is superseded. Do not duplicate complete plans here.
```
